The missing product layer

An API gives you a model. A subscription gives you an experience.

Meo AI is an attempt to build that experience without tying it to one model vendor. Bring user-owned providers or local models, then keep the useful product layer above them.

API

What the raw API gives you

Inference: messages in, model output out. Everything around that request is your responsibility.

  • Model endpoint and capabilities
  • Usage billed by the selected provider
  • No shared product identity by itself
  • No built-in history, projects, permissions or device workflow
m

What Meo AI adds

A persistent product experience above interchangeable models.

  • Meo Account and provider broker
  • Conversation identity and cloud history
  • Files, images and rich native presentation
  • Stop, retry, reconnect and visible agent work
↗

What goes beyond normal chat

The same conversation can grow into real work without handing authority to the model.

  • Workload-aware model routing
  • Execution, bounded subagents and Judge verification
  • Typed system capabilities and explicit approval
  • Remote AgentRuns on a user-owned Linux device
Complete experience

The parts that make an API feel like a product

The goal is not to clone one subscription service screen-for-screen. It is to provide the product primitives people expect while keeping provider choice and local execution open.

Implemented

Conversation runtime

  • Streaming responses with real request state
  • Stop / cancellation and safe reconnect
  • Persistent conversation history
  • Generated and restored titles / summaries
  • Actionable failures and eligible retry paths
Implemented

Multimodal context

  • File attachments
  • Clipboard image input
  • Retained resource state
  • Vision-capability checks before routing
Implemented

Account + BYOK

  • Meo Account OAuth/OIDC identity
  • Encrypted provider credentials behind the Account broker
  • Provider/model selection without exposing raw keys to the browser
  • OpenAI, Gemini, DeepSeek, OpenRouter and compatible broker profiles
Implemented

Agent experience

  • Observable tool activity and decisions
  • Bounded coordination for complex execution
  • Judge verification / repair before final display
  • Native data-only presentation cards
Model routing

Use the right model for the job, not one expensive model for everything.

Meo AI classifies ordinary requests before execution and can route them by workload and capability. The model choice changes; the conversation does not.

Image requests routed only to vision-capable models.

Bounded verification, ranking and repair support.

Title & summary

Cheap background naming and conversation digests.

Intent aware

Chat, reasoning, coding and action requests do not have to share one route.

02
Capability aware

Vision requests require an eligible multimodal model instead of silently dropping the image.

03
Cost aware by design

Small auxiliary jobs such as titles can use a cheaper role than the main reasoning path.

04
Security stays outside

Judge and Execution models can never grant themselves system permission.

Architecture

Models are replaceable. Authority is not.

Meo AI separates user experience from credential ownership and system authority, so adding another model does not also grant it another set of secrets or privileges.

Conversation ≠ model

GPT, Claude, a local model or a device agent can participate without replacing the conversation.

Prompt ≠ permission

Model output, Skills and MCP descriptions are input to policy, never authority.

Cloud ≠ filesystem

Remote orchestration does not require publishing the user's local workspace path.

Disconnect ≠ retry

Reconnect semantics preserve exact request identity instead of duplicating side effects.

From API wrapper to subscription-quality product

What is already real — and what still needs to close the experience gap.

The important line is not whether code exists somewhere upstream. A capability counts as a Meo AI product feature only when its UI, persistence, security semantics and live path are integrated and testable.

Productized now
  • Native MeoUI and browser chat surfaces
  • Streaming, Stop, cancellation, reconnect and retry states
  • Cloud conversation history plus title / summary metadata
  • Chat / Reasoning / Execution / Vision routing
  • Judge verification and bounded coordination
  • Files, clipboard images and vision-aware routing
  • Meo Account provider broker and BYOK boundary
  • Tool confirmation and typed native presentation
Closing the complete-experience gap
  • Full Native ↔ Web conversation parity
  • Projects / durable workspace experience
  • Memory review, scope and deletion UX
  • Richer artifacts, files and diff workflows
  • Usage / cost dashboard across providers
  • Background tasks and notifications
  • Remote device AgentRun live acceptance
  • Polished onboarding that hides provider plumbing from normal use
Available building blocks, not yet claimed as finished Meo UX
  • Full Skills management
  • Full MCP management
  • Long-term memory engine
  • Document / RAG workflows
  • Web search
  • Image generation
  • Scheduled tasks
  • Broad terminal / extension ecosystem
