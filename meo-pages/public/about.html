What it actually does

More than a chat window

Meo AI separates the conversation experience, model choice, execution lifecycle, credentials and operating-system authority instead of putting every responsibility in one prompt.

↯
Implemented

Reliable conversation runtime

Streaming is treated as a real request state, not just text appearing on screen.

  • Streaming replies with ordered request events
  • Real Stop / cancellation semantics
  • Reconnect after transport loss without replaying the request
  • Duplicate event suppression and bounded reconnect attempts
  • Persisted conversation identity, history, title and summary metadata
  • Typed failure state and safe retry for eligible text requests
◎
Implemented

Files, images and vision

Resources are first-class request inputs rather than paths pasted into a prompt.

  • Native file attachments
  • Clipboard image input
  • Queued and retained attachment state
  • Vision-capability checks before routing
  • Automatic selection of a vision-capable role for image requests
◇
Implemented

Native presentation cards

Models can request bounded data-only cards while the installed client decides how to render them.

InfoStatusMetricFileSystem

No arbitrary QML, HTML or JavaScript is executed from model output.

✓
Implemented

Observable agent work

Complex execution can expose coordination and verification information instead of hiding everything behind a spinner.

  • Tool decisions and explicit approval states
  • Coordinator progress surfaced with MeoUI status cards
  • Execution routing details and response summary metadata
  • Bounded verification / repair step for execution responses
Model routing

The same model does not need to do every job.

Meo AI can assign different models to different workloads. A small deterministic router classifies each request first, then selects an eligible model role without making the model itself the security policy.

Architecture

One product, several authority boundaries.

The point of the architecture is not to create more boxes. It is to make sure chat, credentials, local execution and privileged system control can evolve independently.

Conversation ≠ model

A conversation keeps its identity even when a different model or executor handles a later turn.

Prompt ≠ permission

Skills, MCP descriptions and model text cannot grant themselves system authority.

Cloud ≠ local filesystem

Remote work can use opaque workspace references instead of publishing local paths.

Disconnect ≠ cancel

Transport loss can reconnect to the same request instead of accidentally submitting a new side effect.

System actions

Useful access without giving the model the keys.

The native SystemTool path is an explicit opt-in preview. It consumes capabilities and argument schemas from the System AI Router rather than exposing one generic “run anything” system function.

1 · Model proposesSet volume to 30%
2 · Typed capabilityaudio.volume.set
3 · Policy / confirmationApprove exact request
4 · Owning serviceExecute + report result

Approval is bound to the Router-issued request identity. A model, Skill or presentation card cannot approve itself.

Remote agent bridge

Honest status

What is productized, what is preview, and what is still upstream capability.

Meo AI is intentionally not presented as a finished release. The distinction matters: an inherited engine feature is not a finished Meo feature until it has crossed the Meo service, UI, persistence and security boundaries and passed live acceptance.

Implemented in the Meo path
  • Native C++/QML MeoUI chat surface
  • AgentService streaming, Stop, cancellation and reconnect
  • Persistent history plus generated/restored title and summary metadata
  • Active Chat / Reasoning / Execution / Vision request routing
  • Judge verification/repair and bounded high-complexity coordination
  • File and clipboard-image attachment flow with vision-aware routing
  • Native presentation/status cards and tool confirmation path
  • Web Meo Account sign-in, provider broker, model selection and streaming chat
  • Web conversation history persisted through Meo Cloud / Supabase
  • Actionable failure and retry states on supported request paths
Implemented as preview / still under acceptance
  • Typed System AI Router integration for native system actions
  • Remote AgentRun cloud service and device relay
  • Device enrollment, narrow credentials and KWallet-backed meo-agentd
  • Full cross-surface Native ↔ Cloud conversation unification
  • Complete live-provider / Plasma acceptance for every supported path
  • Long-running durability across service restart
Useful upstream capability, not yet claimed as finished Meo product
  • Full Skills management experience
  • Full MCP management experience
  • Long-term memory product UI
  • Document/RAG workflows
  • Web search product surface
  • Image generation workflow
  • Scheduled tasks
  • Broad terminal / extension ecosystem
