API 缺少的产品层

API 给你一个模型。订阅产品给你一整套体验。

Meo AI 想把这套体验重新做出来，同时不把用户锁死在某一家模型厂商里。 你可以使用自己的 Provider 或本地模型，再把真正有用的产品体验保留在上面。

API

原始 API 给你的东西

输入消息，返回模型输出。围绕一次请求的其他体验，都需要你自己处理。

  • 模型端点和模型能力
  • 按所选 Provider 的规则计费
  • 本身没有统一的产品身份
  • 没有内置历史、Projects、权限或设备工作流
m

Meo AI 补上的东西

把可替换的模型放进一个持续存在的产品体验里。

  • Meo Account 和 Provider Broker
  • 统一会话身份和云端历史
  • 文件、图片和丰富的 Native 展示
  • 停止、重试、重连和可见的 Agent 工作过程
↗

不只是普通聊天

同一个会话可以继续变成真实任务，而不是把系统权限直接交给模型。

  • 根据任务类型自动选择模型
  • Execution、受限 Subagent 和 Judge 验证
  • 类型化系统能力和明确授权
  • 在用户自己的 Linux 设备上执行远程 AgentRun

模型路由

让合适的模型做合适的工作，而不是所有事情都用同一个昂贵模型。

Meo AI 会在执行前识别普通请求，并根据工作类型和能力需求进行路由。 模型可以改变，但会话不会因此改变。

02
理解能力要求

图片请求必须进入支持多模态的模型，而不是悄悄丢掉图片。

03
从设计上控制成本

标题之类的小任务，可以使用比主推理模型更便宜的辅助角色。

04
安全权限独立在模型外

Judge 和 Execution 模型永远不能自己给自己系统权限。

一个账号 · 多个界面

会话属于你，而不是属于某一个浏览器或某一个模型。

Web 和 Native 的目标是重新打开同一个云端会话。一次任务可以由 Provider 模型回答， 也可以变成注册本地设备上的 AgentRun，同时保留同一个会话身份。

架构

模型可以替换，权限不能跟着一起乱换。

Meo AI 把用户体验、凭据所有权和系统权限拆开。这样增加一个模型， 不会顺便把更多秘密或系统权限一起交给它。

会话 ≠ 模型

GPT、Claude、本地模型或设备 Agent 都可以参与，而不需要替换整个会话。

Prompt ≠ 权限

模型输出、Skills 和 MCP 描述只能作为 policy 的输入，不能直接成为系统权限。

Cloud ≠ 文件系统

远程协同不需要公开用户本地工作区的真实路径。

断线 ≠ 重做一遍

重连会保留准确的请求身份，避免重复产生有副作用的操作。
