# BAML Chat-Path Wiring TDD Implementation Plan

## Revision outcome

This revision replaces the rejected runtime-client override, eager import, generic
custom-provider branch, UI-only parameter hiding, and smoke-test assumptions with
contracts proven at the production boundaries.

The feature remains a **named custom endpoint**. An administrator declares one or
more custom endpoints with `provider: baml`; each endpoint exposes an explicit,
case-sensitive list of logical BAML client names. A signed-in user selects one of
those names, starts generation through the authenticated named agents route, reads
the result over the existing resumable SSE route, and can read the durable message
through the existing messages route. No new `EModelEndpoint`, database migration,
or public BAML route is introduced.

Three independent final scoped audits found no remaining blocker in the
runtime/build, config/UI/serialization, or route/SSE/persistence contracts. Phase 0
is still the first repository change even though an isolated probe established its
static-routing design: the proof must become a production-owned, repeatable
acceptance test before downstream work proceeds.

## Verified corrections and locked decisions

### 1. Select direct, statically bound generated functions

Do not construct or pass `baml.llm.Client`, `PrimitiveClient`, a string, a map, a
host `RetryPolicy`, or `retry: null` at request time. On BAML/bridge `0.15.0`, those
forms either fail host type checking or panic in the exact `HostTurn_async` and
`HostTurn$stream_async` execution boundaries with `SdkPanic: expected variant, got
string`. Offline prompt rendering is not an execution oracle.

Instead:

- Declare every selectable client and its retry policy in production BAML source.
- Define one **direct LLM function** per selectable client. The functions interpolate
  the same pure prompt helper so the protocol has one prompt definition.
- Generate and call each direct function's exact non-stream and stream entrypoints.
  Do not wrap the LLM function in a normal BAML function: the wrapper receives an
  `_async` entrypoint but no `$stream_async` entrypoint in bridge `0.15.0`.
- Build an immutable JavaScript `Map` keyed by the exact persisted logical client
  name. Each value contains the generated direct `{ take, stream }` pair and
  declarative metadata. Resolve the key synchronously before creating a call.
- A missing or case-mismatched key returns/yields a sanitized `model_error` after the
  worker/native module loads but before generated-function or provider invocation.
  It never falls back to `OpenRouter` or another client.
- Adding a selectable client is one atomic BAML-source, generated-artifact,
  manifest, example-config, and test-fixture change.

The isolated boundary probe selected two different static clients, observed their
different provider model names, and observed compiled retries for both call and
stream creation: `max_retries: 1` produced two attempts and `max_retries: 2`
produced three. Phase 0 makes this proof durable in the repository.

### 2. Keep the native BAML graph lazy and ESM-owned by `@librechat/api`

`@librechat/api` remains a CommonJS package at its public root. Its ordinary import
must not resolve the import-only bridge, initialize generated bytecode, or require
BAML credentials.

- Move the production BAML project under `packages/api` with named sources and a
  package-local generator output. Root BAML sources remain probes only; production
  builds do not recursively copy them.
- Build two dedicated ESM entries in the same `tsdown` configuration as the CJS
  root: a lightweight parent facade at `packages/api/dist/baml/runtime.mjs` and a
  native worker at `packages/api/dist/baml/worker.mjs`. Bundle package-local
  generated code into the worker graph and externalize exactly
  `@boundaryml/baml-bridge@0.15.0`.
- Export `defineConfig([cjsConfig, esmConfig])`, not one config with both formats.
  The CJS config owns only `src/index.ts`/`src/telemetry.ts` with declarations; the
  ESM config owns only `src/baml/runtime.mts`/`src/baml/worker.mts`, with source maps
  and `dts: false`. Set `outputOptions: { codeSplitting: false }` in both so no
  unnamed chunks escape the exact manifest.
- Add one typed CJS-side loader. It performs an intentionally non-static dynamic
  import of the dist ESM file using a `pathToFileURL` derived from `__dirname`.
  This is the documented exception to ordinary static imports because the bridge
  exports an `import` condition only.
- The facade resolves its worker with `new URL('./worker.mjs', import.meta.url)`;
  generation, build, test, and Docker paths never depend on `process.cwd()`.
- Cache successful and concurrent facade loads. Cache a facade link/evaluation
  failure too: Node caches failed ESM evaluation for the same URL, so a corrected
  deployed module requires process restart. Per-invocation worker/provider failures
  are not cached; a later request gets a new worker. Generated functions/native
  values never cross the worker boundary. Return only stable, sanitized errors.
- Register the lightweight `@librechat/agents/baml` class separately; registration
  must not load the native runtime.
- Commit package-local generated source plus a source/toolchain fingerprint. Every
  npm/Bun/Turbo/Docker build verifies that fingerprint without needing the CLI.
  Developer generation and CI install/assert the exact `0.15.0` toolchain through a
  checksum-verified bootstrap script, regenerate, update the fingerprint, and fail
  on a dirty diff. A package-local `chokidar@3.5.3` orchestrator performs an initial
  generation, serializes later `.baml` changes, and runs the corresponding `tsdown`
  watcher. `clean` removes stale outputs. Docker ships package dist, not a parallel
  root SDK and source adapter.

The exact clean manifest is:

```text
dist/index.cjs
dist/index.cjs.map
dist/index.d.cts
dist/telemetry.cjs
dist/telemetry.cjs.map
dist/telemetry.d.cts
dist/baml/runtime.mjs
dist/baml/runtime.mjs.map
dist/baml/worker.mjs
dist/baml/worker.mjs.map
```

No `index.mjs`, `telemetry.mjs`, `runtime.cjs`, `worker.cjs`, internal `.d.mts`,
generated-source directory, spec, debug probe, or source adapter may appear in dist.

### 3. Model BAML as a provider-discriminated custom endpoint

- Append `BAML = 'baml'` to the data-provider `Providers` mirror. Do not add it to
  `EModelEndpoint` and do not renumber existing values.
- Widen the custom-endpoint provider schema to represent BAML. Because
  `configSchema` applies `endpointSchema.partial()`, enforce BAML cross-field rules
  at the public `configSchema.strict()`/`loadCustomConfig` boundary, while preserving
  existing partial behavior for other custom providers.
- A BAML endpoint requires a nonempty `name`, `provider: baml`, and a nonempty
  explicit `models.default`. `models.fetch` is absent or `false`.
- `customParams.defaultParamsEndpoint` may be absent, `custom`, or `baml`; normalize
  all three to `baml`. Reject every other value. Reject OpenAI-only `addParams`,
  `dropParams`, and every `customParams.reasoning*` field rather than silently
  ignoring them.
- Forbid BAML `apiKey`, `baseURL`, `headers`, `directEndpoint`,
  `models.userIdQuery`, and the `user_provided` API-key/base-URL sentinels.
  Provider transport and credentials belong to compiled BAML clients and their
  documented environment variables.
- Treat each `models.default` entry, string or `{ name, ... }`, as a case-sensitive
  foreign key to the compiled-client registry. Discovery may publish an allow-listed
  but uncompiled name. Initialization still creates the normal `ChatBAML`-facing
  function set; its first turn returns/yields the defined sanitized `model_error`, so
  existing `BamlTurnError` content handling and persistence own the outcome. It never
  rejects initialization or chooses another compiled client.
- Add `packages/api/src/endpoints/custom/provider.ts` with the pure
  provider-aware predicate/normalizer shared by endpoint and model discovery. BAML
  discovery publishes `type: custom`, `userProvide: false`, and
  `customParams.defaultParamsEndpoint: baml` without credential resolution, URL
  validation, user-secret lookup, model fetch, or OpenAI configuration.
- Discriminate BAML immediately after endpoint lookup and exact selected-model
  authorization. Use an owned BAML initializer before generic custom credential,
  cache, URL, fetch, and OpenAI-shaped work.
- Set the returned runtime provider to `Providers.BAML` on initialization and on
  downstream provider-config re-entry. The persisted/public endpoint remains the
  named custom endpoint.
- Extend provider re-entry to accept both runtime provider and original endpoint
  identity. For `provider: baml`, `getProviderConfig` requires the exact named custom
  endpoint (for example `endpoint: Team-BAML`) and resolves that entry before
  returning BAML; calling it with literal `baml` alone fails explicitly rather than
  falling back to OpenAI or looking for an endpoint named `baml`. Preserve the exact
  endpoint name on the initialized agent/runtime carrier. Same-endpoint
  summarization/title/activity reuse the existing BAML `clientOptions` and selected
  client. A different BAML summarization endpoint is rejected as unsupported until
  that asynchronous runtime path exists; it never becomes OpenAI-shaped.
- Support only static `tokenConfig` for BAML. Key it by exact logical client name,
  propagate it as `endpointTokenConfig`, and never read/write fetched token config.
  Centralize the side-effect decision in a pure
  `shouldReadFetchedTokenConfig(endpoint)` gate, then perform any allowed cache read
  in a separate guarded statement; the gate is always false for BAML and for static
  config.
  If it is absent, return `endpointTokenConfig: undefined`, perform zero cache
  reads/writes, use the existing `DEFAULT_MAX_CONTEXT_TOKENS = 32_000` host fallback
  before normal output/reserve adjustment, and apply no custom prompt/completion
  price.

### 4. Separate executable runtime state from document-shaped state

`functions`, generated functions, registries, BAML contexts, bridge objects,
clients, and abort signals are request-only. They must never enter
`agent.model_parameters`, Mongo documents, pending/HITL state, checkpoints,
messages, conversations, SSE/JSON payloads, or public DTOs.

- Replace `InitializeResultBase.llmConfig: ClientOptions` in
  `packages/api/src/types/endpoints.ts` with a correlated union. The BAML arm is
  `{ provider: Providers.BAML; llmConfig: Omit<BamlClientOptions, 'functions'>;
runtimeOptions: { functions: BamlFunctionSet } }`; the existing-provider arm keeps
  its current `ClientOptions` and has `runtimeOptions?: never`. Initializer and run
  consumers narrow on `provider`; they do not cast executable state back into
  `llmConfig`.
- Store runtime options on the initialized in-memory agent through a private,
  non-enumerable, symbol-keyed carrier in `packages/api/src/agents/runtime.ts`.
  Do not use a process-global `WeakMap`.
- `initializeAgent` writes only declarative `llmConfig` to `model_parameters`.
  `createRun` reads the carrier and merges it only when constructing final
  `ClientOptions`, immediately before creating `ChatBAML`.
- Make HITL resume capture schema-owned: start from the explicit supported
  generation-parameter allowlist, and hard-deny `functions`, `runtimeOptions`,
  `client`, `createClient`, registry, context, signal, and symbol-carrier values.
  For BAML, pass the resolved `defaultParamsEndpoint`/provider into resume capture
  and parse the candidate state with `bamlSchema`; never overlay the global union of
  OpenAI/Anthropic/Google request keys. Recursively dropping function-valued leaves
  is not sufficient.
- Test document, BSON/JSON, pending action, and public DTO boundaries on success,
  failure, pause/resume, and cancellation.

### 5. Use the published BAML port exactly

- `BamlPromptInput` contains `version`, transcript, current `allowedTools`, and the
  optional abort signal. Validate/consume `version`, transcript, and `allowedTools`;
  serialize the declared BAML arguments to the worker; translate `signal` into a
  worker-owned `BamlCallContext`. Never pass raw `signal` as a generated-function
  option.
- Keep `BamlFailureCode` closed to `unbound | schema_mismatch | model_error |
parse_error`. Unknown compiled clients and model/schema/coercion failures are
  values in that union; no `unknown_client` extension is added.
- `takeTurn` **returns** a failure value. `streamTurn` **yields** a failure value.
- Caller abort and provider/I/O/timeout failures reject, as the port requires. Map a
  caller abort to the existing abort error. Map a deadline or provider/transport
  failure to one stable sanitized transport error; do not turn it into a
  `BamlFailureOutcome`.
- Use exact registry lookup and structural error guards. Never construct a dynamic
  regular expression from a client/model name, so names such as `[` cannot make the
  classifier throw.
- Classification precedence is: caller-abort rejection; unresolved-client failure
  value; transport/provider/deadline rejection; model/schema/parse failure value.
  All non-abort public messages are stable and sanitized: no stack, path,
  environment name/value, credential, native constructor, `$new`, or bridge
  internals.

### 6. Define streaming, retry, deadline, and resource promises

Generated `$stream_async` existence proves stream creation, not progressive pull
correctness. Bridge `0.15.0` showed unreliable `nextAsync()` behavior in an isolated
delayed fixture, so the adapter cannot promise live deltas until Phase 4 proves the
exact production implementation.

- Preserve the BAML-defined retry policy by using direct generated functions and
  passing no host retry override.
- Run each call/stream invocation in a single-use worker. The parent owns these
  non-user-configurable safety constants: `BAML_CALL_TIMEOUT_MS = 120_000`,
  `BAML_STREAM_START_TIMEOUT_MS = 60_000`, `BAML_STREAM_IDLE_TIMEOUT_MS = 30_000`,
  `BAML_STREAM_FINAL_TIMEOUT_MS = 30_000`, `BAML_STREAM_TOTAL_TIMEOUT_MS = 300_000`,
  and `BAML_WORKER_ABORT_GRACE_MS = 250`. Tests inject the clock/timer seam. On
  caller abort or deadline, the parent sends a cooperative abort request and then
  terminates the worker no later than the grace deadline. Never simulate
  cancellation by racing a promise while native work survives in-process. Caller
  abort rejects with the abort type; a deadline rejects with the sanitized transport
  type.
- The parent sends one serializable `{ type: 'start', operationId, mode, clientName,
input }` message; the worker answers only with `ready`, `chunk`, `final`,
  `failure`, or `rejection` messages carrying that ID. The parent uses a monotonic
  `active | terminal` state, accepts one terminal transition, ignores queued/wrong-ID
  messages after it, removes signal/message/error/exit listeners, and terminates the
  single-use worker after final/failure/rejection. Abort sends one `{ type: 'abort',
operationId }` request before forced termination. No worker is returned to a pool.
- The worker invokes the exact generated `$stream_async` creator, then performs the
  blocking public `next()`/`final()` pulls on the worker thread. It does not use the
  observed-unreliable `nextAsync()`/`finalAsync()`, private `_acc`, or a main-thread
  native pull. Each non-null cumulative snapshot is posted immediately; exhaustion
  is followed by one blocking `final()` and terminal post. Parent-owned timeouts can
  terminate the thread even while either synchronous pull is blocked.
- Consumer iterator `return()` aborts upstream work and removes the listener.
  Pre-abort, abort while a pull is pending, abort after a partial, abort during
  finalization, and early consumer return all have one terminal outcome, no late
  chunk, and listener/context cleanup.
- Partial results are cumulative snapshots. Emit only a strict string prefix delta.
  An identical snapshot emits nothing. A non-prefix snapshot or invalid structured
  partial yields one `parse_error` and stops; never append the whole divergent
  snapshot and duplicate output.
- Build transcript tool-result associations in one pass with a `Map`. Enforce
  `MAX_TRANSCRIPT_ENTRIES = 1_000`, `MAX_TRANSCRIPT_TEXT_CHARS = 2_000_000`, and
  `MAX_TOOL_RESULT_CHARS = 250_000`, measured as JavaScript string code units,
  before worker creation. Return/yield a sanitized `schema_mismatch` when exceeded.
- Usage metadata may come only from a documented public generated/bridge surface;
  private `_acc` inspection is forbidden. Bridge `0.15.0` exposes no verified public
  call metadata, so the production adapter omits `meta`. It never fabricates zeroes.
  Existing BaseClient fallback counting/pricing owns production accounting. A
  separate port-contract integration supplies complete public `meta` and proves
  ChatBAML/callback propagation emits it once. If a future bridge adds a supported
  surface, adoption requires an exact pin plus the full Phase 0 compatibility matrix.

### 7. Define UI, parser, and raw-request behavior

- Add `const bamlConfig: SettingsConfiguration = []` and map it at
  `paramSettings[Providers.BAML]`.
- Add `presetSettings[Providers.BAML] = { col1: [], col2: [] }`; verify derived
  `agentParamSettings` is also empty.
- The main `EndpointSettings` renderer must resolve
  `customParams.defaultParamsEndpoint`, matching the side panel and Agent Builder,
  before selecting the settings component and preset columns. Because BAML's arrays
  and columns are empty, it intentionally renders no endpoint-settings panel and
  needs no `settings[Providers.BAML]` component mapping. Endpoint and model selection
  remain in the external endpoint/model picklist populated by discovery. Test both
  surfaces through real endpoint-query data for arbitrary named endpoints; do not
  test a magic display name or call a settings map directly.
- Add explicit BAML conversation and compact schemas to both parser maps and their
  lookup-key unions. The full schema picks exactly `chatProjectId`, `model`,
  `modelLabel`, `chatGptLabel`, `promptPrefix`, `resendFiles`, `artifacts`,
  `imageDetail`, `iconURL`, `greeting`, `spec`, `maxContextTokens`,
  `disableStreaming`, and `fileTokenLimit`, then removes nullish values. The compact
  schema picks the same set except `iconURL`, which remains server-derived.
  `possibleValues.models` may replace only `model` with the first exact allowed
  value; no other defaults or transformations are introduced.
- Strip provider generation fields at both client serialization and server ingress,
  including enforced model-spec reparsing. The explicit deny fixture includes
  `temperature`, `top_p`, `topP`, `topK`, `frequency_penalty`,
  `presence_penalty`, `max_tokens`, `maxTokens`, `max_output_tokens`,
  `maxOutputTokens`, `max_completion_tokens`, `maxCompletionTokens`, `stop`, every
  reasoning/thinking/effort field, prompt cache, provider web/URL tools,
  region/system/provider config, and unknown generation keys.
- Raw callers get the same cleanup semantics as the UI: unsupported generation
  fields are ignored/stripped, not passed to BAML and not persisted. Invalid endpoint,
  model, or cross-field configuration is rejected.
- Encode the named endpoint segment with `encodeURIComponent` in `createPayload`.
  Express already decodes `req.params.endpoint`; do not call `decodeURIComponent`
  again. Move `buildEndpointOption` out of the chat router's shared `router.use`
  stack and register routes in this order:

  ```js
  router.post('/resume', buildEndpointOption, resumeController);
  router.post('/', buildEndpointOption, controller);
  router.post('/:endpoint', requireEndpointIdentity, buildEndpointOption, controller);
  ```

  `requireEndpointIdentity` requires a string body endpoint exactly equal to the
  decoded route parameter before model lookup or job creation. Mismatch or missing
  body identity returns HTTP 400 with exactly
  `{ "error": "Route endpoint does not match request endpoint." }`. Existing
  `/resume` and `/` behavior and their middleware ordering remain unchanged.

### 8. Preserve the real public response contract

The trigger is authenticated `POST /api/agents/chat/:endpoint`. It returns a JSON
"started" envelope and does **not** return SSE. With requested protocol version 2,
assert HTTP 200, response header `x-librechat-generation-protocol: 2`, and exactly
the required body fields `streamId`, `conversationId`, `generationCreatedAt`,
`status: 'started'`, and `generationProtocolVersion: 2`. The authenticated owner
then reads
`GET /api/agents/chat/stream/:streamId` as SSE with `Content-Type:
text/event-stream`, `Cache-Control: no-cache, no-transform`, identity encoding, and
`Connection: keep-alive`, `X-Accel-Buffering: no`, and the same protocol header.
Each normal frame is exactly `event: message\ndata: <JSON>\n\n`, including the final.
Another user cannot read the stream or the conversation messages. The unauthenticated
named POST returns HTTP 401 and `{ "message": "Unauthorized" }` in the JWT harness.

A BAML failure becomes `BamlTurnError`, which the existing `AgentClient` converts to
a `ContentTypes.ERROR` content part. The controller persists it and publishes the
ordinary final `event: message`. It is not a transport `event: error` unless an
unexpected uncaught controller/transport failure occurs. Persistence is awaited and
verified before the terminal event. The durable observable is authenticated
`GET /api/messages/:conversationId`.

For an allow-listed but uncompiled client, the exact final content part is:

```json
{
  "type": "error",
  "error": "An error occurred while processing the request: BAML turn failed (model_error): The selected BAML model is not compiled for this server."
}
```

The endpoint in the stored assistant message is the named custom endpoint. The model
and usage key are the exact logical compiled-client name. `agents.allowedProviders`,
where applicable, contains the exact custom endpoint name, not the literal `baml`
provider discriminator.

## Production interfaces

### BAML source and compiled-client manifest

The production project lives at `packages/api/baml.toml` and
`packages/api/baml_src/`. A shared prompt helper defines the protocol. Each direct
LLM function binds one statically declared client and retry policy. Generated output
lives under `packages/api/src/baml/generated/` and is regenerated atomically.
Every direct function has the same declared BAML arguments: `user_message`, the
versioned converted `transcript`, and `allowed_tools`. The adapter accepts only port
version 1, passes the current bound subset (never the compiled superset) into the
prompt, and maps an unknown/unbound tool name to the existing `unbound` failure code.

The initial production registry contains two real supported clients, not test-only
transports:

| Logical key      | Provider model        | Credentials/transport                            | Retry policy                        |
| ---------------- | --------------------- | ------------------------------------------------ | ----------------------------------- |
| `OpenRouter`     | `openai/gpt-oss-120b` | `OPENROUTER_API_KEY`, `BAML_OPENROUTER_BASE_URL` | `FreePoolBackoff`, `max_retries: 4` |
| `OpenRouterFast` | `openai/gpt-oss-20b`  | `OPENROUTER_API_KEY`, `BAML_OPENROUTER_BASE_URL` | `FastPoolBackoff`, `max_retries: 2` |

Production config sets `BAML_OPENROUTER_BASE_URL=https://openrouter.ai/api/v1`.
Automated tests point that same BAML-owned variable to loopback, so they exercise the
exact shipped functions/registry without shipping fixture clients or changing the
host-call interface.

`packages/api/src/baml/manifest.ts` is imported only by the native worker. It exports
exact declarative names and generated direct function pairs, validates on worker
initialization that every entry has callable `take` and `stream` members and that no
duplicate key exists, and exposes neither through worker messages. There is no
default entry and no fuzzy/case-folded lookup.

Conceptual shape:

```ts
type CompiledBamlClient = Readonly<{
  take: GeneratedTakeTurn;
  stream: GeneratedStreamTurn;
}>;

const compiledClients = new Map<string, CompiledBamlClient>([
  ['OpenRouter', { take: HostTurnOpenRouter_async, stream: HostTurnOpenRouter$stream_async }],
  [
    'OpenRouterFast',
    { take: HostTurnOpenRouterFast_async, stream: HostTurnOpenRouterFast$stream_async },
  ],
]);
```

### Loader result

The lazy loader resolves a frozen parent facade that creates a `BamlFunctionSet` for
one required selected name without consulting the generated registry. It caches
facade module success/concurrency and stable module-load failure, and never exposes
generated modules or bridge values through API exports. A module link/evaluation
failure requires process restart; it is not made retryable by deleting a wrapper
promise. During the first turn, the single-use worker performs exact registry
preflight before a provider request and posts only serializable
partial/final/failure messages on `0.15.0`. A registry miss is a port failure value,
not initializer rejection.

### Request-only runtime carrier

The carrier is internal to the agent initialization/run boundary and has one typed
payload: `{ functions: BamlFunctionSet }`. It is non-enumerable and symbol-keyed.
It is absent from all public agent/data-provider types and JSON schemas.

### Failure result

Unknown exact client:

```ts
{
  kind: 'failure',
  failure: {
    code: 'model_error',
    message: 'The selected BAML model is not compiled for this server.'
  }
}
```

The public message is stable; logs may include the requested name through the
existing structured logger after redaction. Streaming yields the same value exactly
once. Other model/schema/parse failures retain the published four-code union;
transport, deadline, and abort remain rejections.

The worker parent converts provider/I/O rejection to
`BamlTransportError('BAML provider request failed.')` and deadline rejection to
`BamlTransportError('BAML provider request timed out.')`; it preserves the existing
abort type for caller cancellation. The resulting generic controller error parts are
respectively `An error occurred while processing the request: BAML provider request
failed.` and `An error occurred while processing the request: BAML provider request
timed out.`. Native error text is logged only through the redacted structured logger.

The actual `librechat.example.yaml` entry also documents the compiled client's

It does not show fake custom-endpoint credentials. The named custom route is not
guarded by the literal-agents `allowedProviders` check. Wherever an agent policy
does use `agents.allowedProviders`, its entry is the exact custom endpoint name
`Team-BAML`, not `baml`.

The example prices/model availability were verified against the official OpenRouter
pages on 2026-08-10. Recheck them during implementation and update the compiled
client, example, static-token fixtures, and documentation atomically if they changed.

## Workflow closure

### Closure A — compiled runtime selection (BLOCKING)

```text
SOURCE      packages/api/baml_src static clients/functions/retry policies
TRIGGER     compiled dist BAML initializer resolves exact selected logical client
BOUNDARY    lazy CJS -> ESM loader -> generated *_async / *$stream_async functions
DRIVER      single-use native worker, loopback fixture, bounded deterministic timers
OBSERVABLE  fixture request model/prompt/attempts; function deltas/final/failure
```

The test uses the built dist facade/worker and actual generated functions. It selects
two clients with distinct provider models and retry counts, exercises call and
stream, observes at least one text delta before the final result from a delayed
fixture, and rejects missing/case-mismatched names before the fixture sees a request.
An offline resolver, prompt render, private `_acc`, or debug-only method is forbidden
as the oracle. If the exact pinned bridge cannot deliver that pre-final delta in the
worker, Phase 0 stays red: upgrade and exactly pin a proven bridge, regenerate, and
rerun the entire boundary matrix. Buffered output is not accepted as streaming.

### Closure B — request-scoped discovery and settings (BLOCKING)

```text
SOURCE      authenticated user's req.config with two arbitrarily named BAML endpoints
TRIGGER     production endpoint/model config routes and EndpointSettings rendering
BOUNDARY    provider-aware discovery -> defaultParamsEndpoint -> parser/settings maps
DRIVER      route query harness and React query/provider harness
OBSERVABLE  published exact clients, empty controls, cleaned client/server payload
```

This spans `loadCustomConfig`, endpoint/model discovery, actual settings rendering,
client serialization, and `buildEndpointOption`. Direct calls to a map or a magic
display-name assertion do not close it.

### Closure C — authenticated success, SSE, accounting, persistence (BLOCKING)

```text
SOURCE      authenticated user/tenant AppConfig plus named endpoint/model request
TRIGGER     POST /api/agents/chat/:endpoint
BOUNDARY    route identity -> endpoint option -> exact authorization -> ChatBAML
             -> content aggregation -> durable save -> terminal publish
```

## Manual live-provider release gate

After all automated closures pass:

1. Build and start the normal production server path with one real compiled BAML
   client credential configured only through its documented environment variable.
2. Sign in, choose the arbitrary named custom endpoint and exact client in the real
   picklist, and verify BAML has no unsupported parameter controls.
3. Send a prompt, observe incremental output before the final response (the automated
   progressive-pull gate must already be green), reload the conversation, and verify
   persistence and fallback usage/cost accounting.
4. Repeat with a case-mismatched/uncompiled client in a temporary config and verify
   the friendly persisted error contains no runtime detail.

This smoke is a release check, not a substitute for automated route, cancellation,
build, or persistence coverage.

## Review finding disposition

1. **Runtime override:** removed. Direct per-client generated function pairs and
   static retry policies are locked and must be proven through exact built entrypoints.
2. **Import/build boundary:** replaced with a cached lazy CJS-to-ESM loader,
   package-owned generated graph, non-BAML no-load test, and full build/watch/Docker
   matrix.
3. **Settings/UI:** corrected `SettingsConfiguration`/preset shapes, added the
   data-provider provider mirror, resolved the real `defaultParamsEndpoint`, and
   replaced the false display-name Red with a query-driven renderer test including
   `max_output_tokens`.
4. **YAML/credentials/discovery:** specified a cross-field public grammar,
   credential-free compiled ownership, `fetch: false`, shared provider-aware
   discovery, early BAML dispatch, exact client foreign keys, and no side effects.
5. **Failure contract:** retained the published four-code union, uses
   `model_error` for registry/model failures, exact nonthrowing lookup, distinct
   call-return/stream-yield behavior, and rejection for abort/transport/deadline.
6. **Cancellation/retry/completion:** static retries are preserved; operation/pull/
   final deadlines, the full abort/consumer-return matrix, terminal uniqueness,
   append-only delta rules, and linear bounded transcript construction are blocking.
7. **Public API:** added authenticated POST JSON-start, authenticated GET SSE,
   route/body identity, request-scoped config/authorization, real `ChatBAML`, normal
   persisted error content, fallback and complete-meta accounting cases, terminal
   ordering, disconnect/replay, and message-read closures.
8. **Build/serialization/docs:** covers clean/npm/Bun/watch/Turbo/Docker, uses a
   supported Node/TS test boundary rather than Jest `.mjs`, adds BAML conversation
   and compact schemas, runtime non-serialization, example YAML, generated artifact
   ownership, and corrected historical paths.

Category warnings are also closed: provider values are additive; both string/object
client forms and case mismatch are tested; `tokenConfig` is keyed by the logical
client; raw unsupported parameters are stripped at client and server boundaries;
`allowedProviders` uses the named endpoint; generated sources/artifacts change
atomically; branches occur before provider-specific side effects; error predicates
cannot throw; cache I/O uses an explicit BAML/static-token gate; and every changed
connector has a production trigger and observable.
