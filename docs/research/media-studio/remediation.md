Independent integration reviews additionally found and addressed completed-output recovery requiring a revoked credential, the admin router's missing public export, a logout/debounced-auth comparison race, and native failure usage bypassing child or hidden sequential-agent billing. Usage is attributed to its owning agent and deduplicated by the actual model call identity.

Financial admission now persists an initializing receipt before taking a distinct owner accounting grant. Receipt identity and balance generation checks prevent delayed writes from allocating funds against recreated records or restoring a cancelled job's held marker. Permanent account-deletion reconciliation repeatedly removes late unfunded receipts, empty balances, and media ledger writes while preserving funded holds and pending settlements. The final independent review found no remaining concrete issue in these bounded invariants.

Verification batches include 1,052 API provider/storage/policy/title tests, 158 client tests, 78 shared-contract tests, 311 existing chat consumer tests, and the specialist real-Mongo lifecycle/accounting/message/share suites. The final integration pass covers 143 API worker/recovery/accounting/native-request tests, 266 existing chat consumer tests, and 110 real-Mongo media/accounting tests. Counts describe separate, overlapping batches, not a deduplicated grand total. `npx tsc --noEmit` passes in all four changed LibreChat workspaces and the SDK. Production builds pass. The repository circular-dependency scan passes across all five configured module graphs. All 29 workflow YAML files parse.

The SDK patch was applied to a pristine 3.8.7 package downloaded from the lockfile's exact URL and checked against its integrity hash. All 60 patched files match the installed package after newline normalization, and all 32 canonical CJS/ESM contract cases pass against the pristine patched copy. The patch SHA-256 is `43F7C29C2FE6C236C717C3A52FF13C1BF7362223E79283A7C40BB76D387FE969`.

`npm run e2e:media` built the production application. Both browser journeys pass against the local provider: generation/history/preview failure/refinement/chat handoff, and a lost submission response with unavailable receipt discovery followed by the same request ID and exactly one provider submission.

`npm run lighthouse` passes the existing media-disabled conversation scenario with 250 ms per database query: median LCP **3,923.757 ms** (budget 4,500), CLS **0.01683** (budget 0.1), and TBT **64.976 ms** (budget 500). Media replay has separate coverage: a 24-part text transcript uses one authorized batch with two database reads; image batches add one shared File query, and legacy records additionally verify saved references until migration completes. The new CI lane runs runtime, native-consumer/pagination, and media-enabled browser regressions. The default Lighthouse result does not measure provider inference.

See [credential coverage](credentials.md), [retention](retention.md), [operator recovery](recovery.md), [observability and Insights](observability.md), and [SDK patch maintenance](../../../patches/README.md). Imported media bytes are not embedded in portable conversation JSON. Cloud range behavior uses real local HTTP/stream fixtures and SDK boundaries; no paid provider calls or live cloud mutations were used.
