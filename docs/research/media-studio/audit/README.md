# Media Studio: deeper integration audit

**2026-09-19 remediation:** [Implemented fixes and verification](../remediation.md) records the subsequent work across both branches. This audit preserves the baseline findings and diagnostic evidence.

The second pass adds **20 distinct findings: seven P1 and thirteen P2**, bringing the combined audit to **44 findings**. It also strengthens or qualifies several of the [24 first-pass findings](../integration-audit.md) without counting them again. The new defects cross money, retention, request recovery, native conversation compatibility, storage and effective security policy. The recommendation remains to complete these integration contracts before merging. No runtime code has been changed by the audit.

The review follows the boundaries where independent tests can pass while the combined behavior fails: chat and media settling the same balance; request publication interrupted by a crash; a saved key updated through the existing dialog; edited/imported/forked chat content replayed by the SDK; provider constraints projected into the catalog; and UI recovery following an accepted request with a lost response. Diagnostic assertions intentionally confirm defects in the audited head. Their success is evidence of reproduction, not evidence of a fix.

## First-pass corrections and stronger evidence

- **01 clarified by API mode:** legacy `streamEvents(..., { version: 'v2' })` enters the port, while default typed `streamEvents` bypasses it. The typed stream is thenable: awaiting it consumes it, and explicit iteration confirms the same bypass. An intermediate inference that the original probe had not consumed the stream was incorrect; changing to legacy v2 had changed the API under test. `invoke`, `stream`, and legacy v2 still lose image modalities and signed empty text. [HTTP probe covering both modes](probes/sdk-entrypoints.cjs). The direct Google Studio parser independently loses empty signed text too.
- **02 measured:** 24 native text chunks perform 72 serial Mongo queries. At 250 ms injected latency, replay takes **18,801 ms**, versus 47 ms without latency. The 100-part / 75-second figure remains an extrapolation.
- **03 narrowed for native recordings:** an abandoned native recording blocks retirement/account deletion after entering attention state, but it holds **zero media permits**. Paid worker capacity and chat-owned native content are different ownership cases.
- **04 reproduced across owners:** three cleanup failures prevent another owner's queued job from dispatching. Changing only the failed delete to success lets that same job submit, settle, and succeed.
- **06 qualified:** native parts have a working optional TTL when a source deadline is supplied. The current host omits the deadline, retirement does not purge payloads, and duplicated job text survives even when the private part TTL works.
- **13/14 physically reproduced:** legacy Files deletion removes only the original; the thumbnail remains on disk, the retired record leaves the expiry sweep, and the public Files projection still returns it. Shared media storage removal deletes both as a control.
- **19 broadened:** four real schema/catalog-accepted provider combinations are rejected by adapters. This is the same fragmented-validation problem as the comparison form, not four additional counts.
- **Diff attribution corrected:** the first table named the target tip as the comparison base. The audit used the triple-dot diff; the table now names the actual merge base explicitly.
- **Transport suspicion rejected:** installed Axios 1.20.0 enforces streamed `maxContentLength` after decompression. Real oversized chunked and gzip responses fail; reading the Media wrapper alone would have produced a false positive.

These revisions are part of the audit result. The reports do not claim every suspicion was valid, every provider failure is free, disabling creation must revoke existing content, or provider-account binding should be removed.

## Integration work that removes recurring debt

Keep the durable media worker and chat invocation ownership distinct. Reuse policy, accounting, storage, content projection and observability contracts at their shared boundaries. Moving code into a generic helper without unifying the invariant would leave the same maintenance burden.
