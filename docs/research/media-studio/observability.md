# Media observability and Insights

Media uses the host's existing Prometheus registry, OpenTelemetry tracer, and Langfuse SDK handler. Existing telemetry enablement, exporter destinations, sampling, tenant routing, and identity policy still apply. Media does not create another exporter or accounting ledger.

`media_lifecycle_events_total` and `media_lifecycle_duration_seconds` report execution attempts, durable phase changes, settlement, accepted cancellation requests, and cleanup attempts. Labels are bounded API, operation, phase, execution owner, event kind, and result values. `media_queue_wait_seconds` measures queue age when a worker claims queued work. Retries and repeated cancellation requests are observations, so these counters are not unique job totals. The durable totals live in Insights.

Job IDs, tenant IDs, and durable versions correlate OpenTelemetry observations across worker restarts. They never become metric labels. The SDK handles native chat's model traces. Studio submissions and title calls reuse that same SDK handler and `buildLangfuseConfig`; callback input and output contain fixed omission markers, while available usage metadata is retained. Prompts, provider response bodies, signed continuations, credentials, and media bytes are never included in lifecycle events or these callbacks. Async provider polling is represented by worker observations, not fabricated repeat model submissions.

Insights gains a separate Media Studio section using the existing date-range controls and paginated offering breakdown. The query counts accepted Studio jobs created within that range and their current outcomes; native chat recordings are excluded. Each job joins its existing Transaction receipt by tenant, owner, and job identity. Debt collection is not counted as another media cost. Reported, estimated, operator-confirmed, legacy unclassified, and still-unknown costs remain distinct; reconciliation can update displayed amounts and outcomes.

Tenant administrators and principals with the existing tenant-wide `READ_INSIGHTS` capability may view Studio aggregates, even if no agents are configured. An agent-specific `VIEW_INSIGHTS` grant reveals only those agents' chat activity and does not confer Studio access. The authenticated tenant determines the query scope. The public query cannot request a different tenant or promote itself to media access. No prompts, file paths, owners, or recovery evidence are returned in Studio aggregates.

Validation uses standalone MongoDB for tenant/owner boundaries, zero and unknown cost semantics, legacy and operator attribution, native exclusion, date filtering, and pagination. Worker tests cover cancellation across restart and exporter failures without changing provider work or settlement. Focused API tests cover metrics route normalization/upload classification, safe trace payloads, existing Langfuse policy injection, initialization of the first tenant-only tracing destination, and authorization; client tests cover the Media section, empty state, and pagination. Root integration verification covers the consumed SDK build, all workspace typechecks, browser journeys, and Lighthouse.
