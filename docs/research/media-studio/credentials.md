# Media provider credentials

Studio resolves connections from the existing endpoint configuration and saved-key store. It shares safe user/tenant header substitution, endpoint-wide headers, Google auth-header handling, proxy routing, and saved-key expiry checks. Jobs bind to the effective provider account; extending an unchanged key's expiry or editing unrelated saved fields preserves continuation, while replacing the effective key does not.

| Connection           | Supported credential source                                                                          | Scope                                                                                                                                                                                    |
| -------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Builtin OpenAI       | `OPENAI_API_KEY`, or the existing user-provided OpenAI key                                           | Uses `OPENAI_REVERSE_PROXY` and endpoint headers.                                                                                                                                        |
| Builtin Google       | `GOOGLE_KEY` / `GEMINI_API_KEY`, or the existing Google saved-key envelope                           | Preserves `GOOGLE_REVERSE_PROXY`, `GOOGLE_AUTH_HEADER`, and endpoint headers. Ordinary text calls retain chat's credential-validity behavior; new media work checks the dispatch window. |
| Custom endpoint      | The named endpoint's configured or user-provided key and URL                                         | Reuses its credential name, headers, secret envelope, and supported OpenRouter routing policy.                                                                                           |
| Direct provider      | Declared integration key, or a user-provided key under `credentialName`                              | Provider adapters supply their protocol and authentication header defaults. Shared credential names must use the same stored format.                                                     |
| Vertex               | Explicit `endpointRef.kind: vertex` with a service-account `keyFile`, optional project, and location | Supports configured Google image/video models. This does not automatically reuse arbitrary chat Vertex credentials.                                                                      |
| Builtin Azure OpenAI | Not supported by the media integration schema                                                        | Chat/title Azure configuration remains supported by the shared title resolver. Studio requires a separately supported provider connection.                                               |

Credentials and per-request headers remain private. Credential binding excludes dynamic user/message headers; transport policy and headers are resolved for the requesting principal. Public output downloads use the separate credential-stripping and destination-validation path. A proxy does not grant access to destinations forbidden by the effective media network policy.

Provider coverage is declared by each adapter and the shared model constraints. An existing chat/tool configuration is not evidence that every operation is available in Studio. Configuration validation and the catalog expose the supported operation set before submission.
