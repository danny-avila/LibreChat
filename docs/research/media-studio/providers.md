# Provider research: Google and the wider media ecosystem

Retrieved **2026-09-15 UTC** from the official documentation linked below. This is a documentation audit, not an account-access or paid-generation test. Model names are examples observed on that date, not proposed permanent defaults. Availability, region, account tier, API version, and deprecations need validation for each enabled deployment. OpenAI is covered in [openai.md](./openai.md).

The strongest architectural finding is that a provider is not one capability or one protocol. Google alone exposes conversational multimodal output, synchronous image generation, stored interactions, and long-running video operations. A studio needs adapters for specific **provider + API surface + model + operation** combinations.

Start breadth discovery with the [OpenRouter survey](openrouter.md) and its dated public catalog
snapshot. OpenRouter's dedicated image and video APIs are an initial integration path alongside
native providers. The research below identifies native capabilities and additional routes that a
gateway may expose differently or not cover.

### Preserve the whole native response

The current Gemini image guide explicitly warns that `.output_image` and `.output_text` do not capture interleaved output: `.output_image` is the last image block, while ordered `steps` preserve the response. Legacy `generateContent` represents output as content parts. Both require an adapter that preserves text/image order, multiple assets, finish/safety outcomes, and provider usage. [G1, G2]

Multi-turn editing also needs provider continuation state. Interactions can chain `previous_interaction_id`; stateless use instead requires replaying history including unmodified opaque thought signatures and tool-result signatures. The latter are adapter-owned continuation data, not material to display as an image caption or expose as ordinary user-visible text. A flattened prompt plus an output image does not preserve the same conversation. [G2, G8]

Model differences matter even within native images. The guide distinguishes Flash Lite Image, Flash Image, and Pro Image; it says Lite is not optimized for multiple references or sequential editing, while interleaved story examples use Pro. Supported input modalities and output sizes vary. These are capability entries to verify, not global `supportsImages` flags. [G1]

### Lifecycle, storage, and cancellation

| Workflow                | Evidence                                                                                                                                                                                                                                                                    | Required distinction                                                                                                                                 |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stored interactions     | Default retention is 55 days on paid tier and one day on free tier. Paid projects can configure shorter windows. `store=false` prevents later `previous_interaction_id` continuation and is incompatible with background execution. Explicit deletion is supported. [G2]    | Expose the tradeoff between provider storage, server-side continuation, and background execution; keep LibreChat's durable asset record independent. |
| Background interactions | Documented states include `in_progress`, `requires_action`, `completed`, `failed`, and `cancelled`. `POST /interactions/{id}/cancel` stops a running task; deletion removes its stored record. The docs describe a possible delay before cancellation becomes visible. [G9] | Cancelling execution and deleting history are different actions. Verify operation/model support before enabling a cancel control.                    |
| Veo operations          | Generation returns an operation; polling establishes completion. Generated videos are stored for two days, then removed. Extension results have their own retention period. [G4]                                                                                            | Persist operation identity, ingest results promptly, and support recovery after the browser closes.                                                  |
| Google webhooks         | The catalog includes interaction completion/failure/cancellation and `video.generated`. It documents signature verification and acknowledges delivery retries. [G10]                                                                                                        | Webhooks can complement polling; validate support for the chosen endpoint/model and authenticate, deduplicate, and reconcile callbacks.              |
| Google Files            | Files are automatically removed after 48 hours and can be deleted earlier. [G11]                                                                                                                                                                                            | A provider file ID is a temporary transfer/reference artifact, not the durable asset identity.                                                       |
| Cloud Veo               | `predictLongRunning` returns a full operation name; `fetchPredictOperation` retrieves status and Cloud Storage output locations. [G7]                                                                                                                                       | Store the deployment and operation together; inject an authorized Cloud Storage client rather than treating `gs://` as a browser URL.                |

Veo's parameter combinations have constraints: reference-image support, extension, duration, resolution, and audio differ by model. For example, the guide ties higher-resolution output and reference workflows to duration restrictions and limits extension resolution. A seed is documented as improving consistency without guaranteeing determinism. Validate the entire request combination on the server. [G4]

Omni is another example of why broad marketing descriptions cannot become validation rules. Its introduction describes native audio/image/video input reasoning, but its limitations explicitly say uploaded audio references are unsupported in the current API. Uploaded-video editing/extension also has regional restrictions, while editing previously generated videos is treated differently. Do not expose a generic audio-reference picker from the introduction alone. [G3]

### Credentials, privacy, and availability

Gemini Developer API examples use a project API key; Cloud examples use OAuth/IAM credentials with a project and location. A credential entry therefore needs a typed deployment mode, not merely a provider name and secret string. The client should receive available capabilities, never server credentials. [G1, G7]

The Gemini terms distinguish paid and unpaid services: unpaid-service content may be used to improve Google's products and reviewed by humans; paid-service prompts/responses are not used for that improvement, while limited logging and other terms still apply. Interaction storage, file expiration, and these data-use terms are separate concerns. Do not label a provider globally as having “no retention.” [G12]

Deprecation data needs an operator-visible place in the catalog. As one concrete example, the deprecation page lists `gemini-2.5-flash-image` for shutdown on October 2, 2026. Some replacement strings in that page differ from the image guide's examples; resolve this with the live model catalog and an authorized account before choosing a default. [G1, G13]

Aggregator support can widen reach to models such as additional FLUX variants, Kling, or other regional video services, but those are not individually validated here. An aggregator model is a distinct deployment with its own schema and terms; it does not replace the provider adapter contract. Self-hosted image/video engines are another potential route and need a separate operational investigation.

## Recommendation impact

These are design recommendations derived from the evidence above:

1. **Start catalog discovery with OpenRouter and validate both gateway and native paths.** Prove an OpenRouter image operation, native Gemini mixed output and a real edit conversation, then prove an OpenRouter or native video job survives disconnect/restart and imports its output. Choose exact routes after validating account access, API stability and allowed regions; evaluate Omni and Veo as different native candidates rather than assuming Veo is Google's only generation API.
2. **Make the capability catalog operation-specific.** Describe input roles such as mask, reference, initial frame, final frame and source video; valid combinations of duration, dimensions, resolution and audio; output modalities; lifecycle/continuation modes; deployment location; and model deprecation. Distinguish unsupported from not yet verified.
3. **Own the job and asset lifecycle in LibreChat.** A successful provider call and a durably imported asset are separate milestones. Persist job/attempt/provider identifiers, ordered output blocks, provenance, actual usage, delivery expiration, and continuation references. Provider URLs and remote IDs must not become the only stored history.
4. **Separate remote cancellation, local stop-waiting, and deletion.** Represent cancellation requested until the provider confirms; reconcile success racing cancellation. Cancellation does not automatically mean a refund. Retry result download separately from resubmitting paid generation, and avoid blind retries when submission outcome is unknown.
5. **Treat media transfer as an adapter responsibility.** Support bytes/base64, expiring HTTPS, provider uploads, and authorized cloud object references. Validate file ownership and content constraints, stream large transfers with bounds, authenticate provider callbacks, and use controlled network fetches rather than arbitrary server-side URL retrieval.
6. **Keep extensibility narrower than a workflow engine initially.** Typed provider adapters plus endpoint/model descriptors can cover the observed diversity. Broad model hosting, LoRA training, storyboarding, full timelines, audio production, and fine-tuning are separate product increments with substantially different operational requirements.

Before an implementation is considered validated, run account-authorized probes for the chosen API/model pairs: one generation, one supported edit/reference request, blocked output, disconnect/recovery, duplicate callback, delivery expiry, cancellation race, credential rotation, and an unknown submission outcome. No such billable probes were run in this research.
